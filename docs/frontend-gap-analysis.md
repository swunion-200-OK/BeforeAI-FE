## 원격에서 이미 반영된 수정

PR #18에서 HPKE 구현, 목록 커서 수집, 요청·대시보드 집계 보완, 로그 이력과 SSE 재연결 처리가 들어왔습니다. PR #23은 인증·승인·관리자 API를 배포 백엔드 계약에 맞추고, 서버에 없는 기능을 구분했습니다. 따라서 이전 검토 문서의 “HPKE 미구현”, “페이지네이션 누락”, “API 필드 불일치” 지적은 최신 원격 기준으로 갱신했습니다. HPKE 파라미터와 정책 변경 서명 규칙은 아직 서버와 확인해야 합니다.

## 백엔드 계약 후속 변경 (`fix/backend-contract`)

- 실제 백엔드는 로그 서명 대상 형식을 정의하지 않습니다. 실제 서버 모드에서는 서명을 검증했다고 표시하거나 잘못된 서명으로 로그를 숨기지 않고, 미검증 상태를 안내합니다. 모의 API에서는 기존 Ed25519 검증을 유지합니다.
- 실제 서버는 프로젝트 담당자 변경 API와 승인자의 별도 수정 요청 API를 제공하지 않습니다. 실제 서버 모드에서는 담당자 편집과 수정 요청을 실행할 수 없다고 표시하고, 모의 API에서는 기존 시연 동작을 유지합니다. 부서 관리자가 담당자 창에서 관리자 전용 `/admin/users`를 호출하던 경로는 제거했으며, 관리자 화면의 비활성 담당자 표시용 사용자 조회는 유지합니다.
- 실제 서버의 거부 처리에서는 요청 전체가 거부되지만 사유가 저장되지 않습니다. 거부 확인창에서 이 점을 알리고 사유 입력을 받지 않습니다.
- 후속 확인: `npm test -- src/api/contract.test.ts` 통과 (84개). `VITE_API_BASE_URL=/api/v1`로 실행하고 API 응답을 브라우저에서 가로채 부서 관리자 프로젝트 상세를 확인했습니다. 담당자 변경 미지원 문구가 표시되고 `/admin/users` 요청은 발생하지 않았습니다. 실제 백엔드에 연결한 브라우저 확인은 아닙니다.
